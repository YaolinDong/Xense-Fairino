# 身体高度与姿态调节

模块位于 `apps/fairino_upper_probe/body_control/`，本页命令均从仓库根目录执行。单关节调节入口为 `bash run.sh joints --group body`。

## 运行

离线演示，不连接机器人：

```bash
bash run.sh body --demo
```

只读实机状态，不使能、不加载运动控制器：

```bash
bash run.sh body --check
```

确认竖直基准后运行：

```bash
bash run.sh body
```

连接 `fairino@192.168.58.1`，复用原程序的 SSH 密码输入。需先退出原单关节程序、TCP 或 VR 遥操；新程序与它们共用控制器锁，不能同时接管上半身。

窗口启动后使能全部 J1～J20 并保持当前位置。选择高中低预设或修改数值只改变输入；点击“执行到目标”才运动。空格中止并保持使能；Esc/关闭窗口退出并下使能全部关节。切换窗口或工作台功能页会暂停当前运动、保持使能；切回后需要重新点击执行，未完成的目标不会自动继续。头部与双臂保持原关节角度，身体移动会带动其空间位置。

## 竖直参考：已保存用户声明的基准

用户确认的合理低位是 J18=-80°、J19=130°、J20=-55°。这是一个姿态参考，不是三个关节各自的机械限位。

这组角度之和为 -5°；旧直立参考 [-10°,15°,0°] 之和为 +5°，两者相差 10°。仅凭编码器与尚未标定的模型，不能认为两组胸部都相对地面竖直。

本项目配置已保存 `upright_confirmed=true`，标定时间为 2026-10-12 18:01:33，三轴角度和约为 -4.977568°。这是用户声明当前胸部竖直后保存的参考，不是 IMU 重力测量或完整几何标定；若配置缺失或标志为 false，实机运动入口仍会拒绝启动。

如果用户已把胸部摆到所需的竖直姿态，退出原调节程序后，可运行：

```bash
bash run.sh body --calibrate-upright
```

这条命令的含义是“用户声明当前胸部竖直”。程序只读当前关节角度，保存 J18+J19+J20 的角度和，作为本程序前倾 0°；它不自动测量重力方向，不使能，不移动，也不改变机器人编码器零位、SDK 或驱动器参数。保存前会备份本机配置。

## 用户指定的软范围

| 项目 | 规则 |
|---|---|
| 升降 | 低位 0%、中位 50%、高位 100%；模型估算总行程约 425.3 mm |
| 前倾 | 相对标定竖直姿态 0～45°；暂不开放后倾 |
| 左右侧倾 | -15～+15°，左负右正；仅在高度≥90%且前倾≤5°时开放 |
| 腰部旋转 | -90～+90°，右负左正 |
| 运动速度 | 每个运动关节最高角速度，默认 5°/s，可输入任意有限正数；没有 3°/s 等固定上限 |

“接近高位”具体定义为升降行程上方 10%。要在侧倾状态下降低高度或增加前倾，轨迹先把侧倾回正，再进行升降/前倾。由低处前往带侧倾的高位目标，则先升高，再侧倾。侧倾条件同时在界面和机器人端规划器检查。

没有重新加入旧程序的 ±3°相对位移限制、实测超速退出、路径跟踪误差中止；到位误差中止也未启用。轨迹结束表示下发的时间轨迹完成，需查看实测反馈判断真实到位情况。保留原有急停输入、硬件故障、反馈/SSH 心跳、控制器独占及退出下使能逻辑；没有修改底层驱动器保护。

## 模型与高中低参考

RD53 20261030 URDF 的两段长度为 360/380 mm。折叠关节与实机同向，工作台和 Fairino QP 使用 j18 = 实机 J18 − 竖直参考角度和、j19 = J19、j20 = J20。竖直参考通过用户实机姿态标定，不使用模型零位代替地面竖直。

计算两连杆末端高度及前后位置，固定低位参考的前后位置，求同一折叠分支的逆解，再用 J18 补偿胸部前后倾角。高中低切换在模型中保持胸部姿态；升降参考是折叠结构上端，不是机器人总高度或离地高度。侧倾和腰旋转沿实际机械轴调节；全身连杆尺寸/轴方向仍需实机验证。

折叠关节逐轴的编码器零位偏置尚未完整标定，因此实际升降毫米数、前后位置保持效果仍需实测。标定“竖直参考”确定的是三轴角度和的姿态基准，并不完成全部几何标定。前倾和左右侧倾按腰部旋转前的机身方向定义；转动腰部不会同步旋转倾斜指令的坐标方向。

高位选择 J19=15°，参考此前用户测试过的直立姿态的中间关节角。为保持前后位置及新标定的胸部方向，J18、J20 会随之重新计算，不照搬旧的 [-10,15,0]。

以下为角度和 -5°时的历史近似表；本项目实际以 body_config.json 保存的 -4.977568° 为准：

| 基准 | 相对低位升高（模型估算） | J18 | J19 | J20 |
|---|---:|---:|---:|---:|
| 低 | 0 mm | -80.000° | 130.000° | -55.000° |
| 中 | 212.639 mm | -56.490° | 90.212° | -38.722° |
| 高 | 425.278 mm | -17.940° | 15.000° | -2.060° |

重新标定竖直参考会改变 J18 补偿值；J19、J20 的高低参考与相对升降量不因此改变。前倾指令在保持折叠结构上端位置的基础上调整上身姿态，不保证胸部上的每个点空间位置不变。没有装载未经确认的 URDF 关节限位，也没有新增碰撞检测。

若启动时身体不在这条升降路径上，点击执行后会先对齐路径；超出新姿态范围时先向范围内恢复。这个步骤在界面阶段说明和日志中可见，启动本身不自动对齐或回高位。

## 控制与验证

本机 GTK → SSH → .1 上的 Python 后端 → ROS 2 `FollowJointTrajectory` → 临时 `fairino_upper_identify` 控制器 → 厂家硬件接口 → 电机。沿用 ROS_DOMAIN_ID=0；不调用 SDK 的 RobotWaist，也不修改全局服务配置。

轨迹带位置、速度、加速度节点，使用 ROS JTC 五次插值。通过各段 Bezier 导数控制点的上界计算时长，保证计划轨迹的每轴速度不超过用户输入值。该数值是轨迹速度，不是以测得速度触发退出的阈值。

文件：`body_core.py`（模型和轨迹）、`body_robot.py`（ROS 后端）、`body_keyboard.py`（界面）、`body_config.json`（参数）、`logs/`（本程序日志）。共享的通信与控制器生命周期从上级关节模块复用。
