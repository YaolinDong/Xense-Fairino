# fairino_ik 集成方案（新增遥操 IK：手臂 + 躯干）

分支：`feat/pink-ik`。新增 IK 选项 `fairino_qp`，与本分支已有的 `native / vendor / tron2` 并列，**不改动现有三种的默认行为**（默认仍为 `native`）。

> 背景说明：`tron2` 是本仓 `feat/pink-ik` 上 `ec52e81`（limfxin，2026-11-11，未合入 main）引入的后端，把 TRON2 项目的 MIT C++ QP 核心 vendored 到 `third_party/tron2_ik/`，并用 ART7 DH 生成模型。它与 fairino_ik 无代码关系；fairino_ik 只是参考了 TRON2 的实现形式（Pinocchio + QP）。下文把 tron2 当作**本仓内现成的接入模板**来复用。

> 状态：2026-11-19 审查后修订，用户已确认「已确认的行为决定」一节并同意开始执行。

## 目标

PICO 遥操可选 `fairino_qp`：用 `fairino_ik` 的 C++ QP 解双臂 14 轴 + 躯干 5 轴，TCP 用本仓工具点，外层沿用现有腕部保护与独立 FK 校验。

## 依赖

- 源码：`third_party/fairino_ik` 是 git submodule，指向 `git@github.com:XenseRobotics-AI/fairino_ik.git` 的 `main` 分支，固定在 `dd8cdc5`（`pin==4.1.0`、`eiquadprog==1.3.2`），**不修改上游源码**。上游无 LICENSE 文件，在 `THIRD_PARTY_NOTICES.md` 记录来源。克隆本仓后需 `git submodule update --init third_party/fairino_ik`。
- 安装：参照 `tools/ik_experiments/setup_tron2_ik.py` 写 `setup_fairino_ik.py`，依赖与编译产物都放在独立缓存 `.local/fairino-ik/`，与 tron2 缓存分开，不向 PICO 环境 `pip install`。
- 解释器与 PICO 相同（`.local/pico4/env/bin/python`，Py3.12，numpy 2.5.4）。C++ 扩展只用 `pybind11/stl.h`，不依赖 numpy ABI；运行时不 import Pinocchio 的 Python 绑定，仍用 PICO 环境的 numpy。上游 `pyproject.toml` 里的 `numpy==2.2.4` 对本集成不适用。
- **两套 Pinocchio 不能同进程混用**：tron2 用 3.9.0 且以 `RTLD_GLOBAL` 预加载。`fairino_qp` 的加载器发现本进程已加载 `tron2_ik` 原生库时直接报错；需要原生库的 `fairino_qp` 测试在独立子进程里跑。扩展的共享库只能解析到 `.local/fairino-ik/`，不能解析到 `/opt/ros` 或 tron2 缓存。
- 依赖缺失时启动即报错，**不得静默回退到其它 IK**。

## 当前关节映射（RD53 20261030）

工作台和遥操使用厂家 RD53 20261030 URDF。双臂为 J1–J14；J15 对应头部、J16 对应腰旋转、J17 对应侧倾，模型编号与实机一致。头部在双臂 IK 中固定，工作台按实测角度显示。躯干链按 j20、j19、j18、j17、j16 排列。编码器到模型的换算仅在 J18 扣除身体程序的竖直参考角度和，返回硬件角时加回该参考。

求解用 URDF 按厂家文件的 SHA-256 校验。两侧手臂使用 `tcp_core.BOUNDS_DEG`；将 CAD 导出的微小轴向偏量、直角截断恢复为 ART7 DH 名义值，固定安装座与躯干几何使用 RD53。原生求解模型和接收端共用本仓迁移前的软件角度限位，J18 按竖直标定校正。模型来源与坐标见 [遥操模型](../../scripts/pico4/fairino/models/README.md)。

## 工具点

用本仓 `models/taccap/tool_config.json` + `apps/fairino_tcp_probe/tool_frames.py`（`for_arm()`）：

- 法兰模式：腕心偏移 `FLANGE_OFFSET_MM = (-106,0,0)`，已有真机校验记录（`apps/fairino_tcp_probe/analysis/`）。
- 夹爪模式：CAD 张开姿态两指尖中心，固定点，不随开合变化；README 注明实机前需核对抓取点。

不用 fairino_ik 自带的 `left_flange/right_flange`（腕部 −x 0.114 m，网格估计）。末端帧取 `left_waist2_Link / right_waist2_Link`，再右乘本仓的 腕心→法兰→工具 变换。

## 坐标系

fairino_ik 世界系 = `Rz(+90°)·base_link`（x 前 y 左 z 上，原点 base_link，固定）。本仓 TCP 是各臂 DH 基座 / 胸部系，随躯干动。躯干参与求解时，目标必须放在 base_link 固定系：PICO 增量在该系内积分；胸部系 → base 系用与 seed 相同的参考关节角经 URDF 正解换算，实测值只用于保护检查。

精度范围：0.02 mm / 0.01° 只对手臂链成立。J18–J20 逐轴零位未标定（只标了角度和），躯干参与时世界系位置是模型估算。

## 已确认的行为决定

1. **只握一侧 Grip**：松开侧关节保持不动，丢弃求解器给它的解；它的 TCP 随躯干移动。
2. **躯干活动范围（第一版保守）**
   - 实测躯干换算后超出软件限位则拒绝启动。低位边界按当前标定、支点偏移和仓库原限位计算，另加 0.5 个百分点的软件余量。VR 预设下位仍为 66.7%。
   - 躯干解投影回 `body_core` 的身体量（高度、前倾、腰旋转），折叠支点的前后偏移保持启动时的值，不离开升降路径。
   - 2026-11-19 设计时修订（待用户确认，见「第 2 步设计」）：侧倾第一版锁定不动；躯干接近包络边界时提前减速并停在边界，手臂按实际躯干复解并校验。原表述「越界即保持并报错」会让躯干几乎不可用，因为 QP 的解几乎总带一点侧倾分量。
3. **躯干限速**：`torso_velocity_limit` 只限单次迭代步长，限不住每周期位移。每个周期按三段执行：
   - 只解手臂（躯干固定在参考值）；达到容差则躯干不动。
   - 够不到时解 19 轴，取躯干方向，投影到身体量。
   - 躯干增量按每轴 ≤ `default_speed_deg_s`（5°/s）并限制加速度后，手臂在该躯干下复解；独立正解校验通过、且手臂解不比「手臂不动」更差才下发，否则报错并进入现有的全轴保持。躯干减速途中误差可以暂时增大。
4. **一键复位（参考 lerobot-xensehand 的 PICO 遥操）**
   - xensehand 的做法：A/X 上升沿触发 → 清遥操状态 → 机器人回初始位 → 等待到位 → 用实测 TCP 重新对齐手柄。本仓的 Home 流程已是同一结构（松开 Grip 且静止后开始，握 Grip / 空格 / 再按一次中止，到位后重握 Grip 重新对齐）。
   - `fairino_qp` 下复位 = 双臂回 Home，**随后**躯干回到本次遥操开始时的姿态。先臂后身，减小躯干运动时的力臂。
   - 触发键：沿用右摇杆按压 / `h`，另加右手 A 键上升沿。`--freeze-buttons` 开启时 A 仍是冻结键，不触发复位。X 键保留给灵敏度双击。
   - 躯干回程用 `body_core.plan()` 的分段轨迹（先回正侧倾 → 对齐升降路径 → 升降与姿态），经 `fairino_qp` 的躯干通道逐周期下发，校验与遥操相同，中止条件与 Home 相同。
   - 其它三种 IK 的 Home 行为不变（仍只动双臂）。

**第 1 步结果（2026-11-19，已完成）**
- `third_party/fairino_ik/` 18 个文件与上游 `09a5674` 逐文件一致；依赖只解析到 `.local/fairino-ik/`；先加载 tron2 再加载 fairino 会被拒绝。
- 厂家 URDF 手臂链对 DH：法兰 0.0081 mm / 0.0038°，夹爪指尖 0.0217 mm（实际法兰到指尖力臂 207.5 mm），超过 0.02 mm。原因是手臂链的直角截断成 1.5708 和末轴 4e-5 rad 的偏量。求解用模型把这两处还原成 DH 精确值后，两种工具模式都降到 1e-12 mm 量级，阈值未放宽。
- Pinocchio 对本仓 numpy 正解的整链一致性 1.4e-12 mm；身体量与 URDF 胸部姿态相差 0.0008°、支点高度 3e-9 mm。
- 耗时（本机，含 Python 封装）：手臂可达时 1 次迭代，约 0.5 ms，其中 C++ 0.05 ms；手臂够不到时固定躯干会跑满 500 次迭代约 17 ms，所以逐周期求解必须限制迭代数。
- 三个 Home 预设下机身避障盒最小间隙 29.5 mm，高于 10 mm 下限，避障保持开启。避障只覆盖上游估计的法兰端点，不含夹爪几何。
- 最近的真机日志（2026-11-13）躯干在高度 16%，属于 `fairino_qp` 不可用的低位，使用前需先升到约 1/3 以上。该姿态偏离升降路径 0.16°。

- 肘部翻转的原因：fairino_ik 的 Home 姿态任务是手部零空间里的拉力，不能让肘部越过伸直这个奇异位形。原生 fairino_ik 只动手臂时同样会翻（Home 权重 1、500 次迭代，12 组里 9 组）；它躯干参与时能回来，是因为单次求解里躯干不受限速。
- 修法，全部用 fairino_ik 自身的能力和配置，不改其源码：
  - 生成给求解器的 URDF 里肘部 J4/J11 下限设为 10°；肘部低于 10° 时拒绝求解，提示先回 Home。
  - 手臂求解启用 fairino_ik 的 Home 姿态任务（`posture_weight = 1`，目标为当前所选 Home 预设）；姿态目标每周期最多向 Home 移动 30°/s。
  - 每周期手臂关节步长由 fairino_ik QP 内部的速度上界限制在 360°/s（`default_velocity_limit × dt`），此前近奇异时单周期可达上万度/秒。
  - 迭代上限 40；外层「手臂解不得比不动更差」在 0.02 mm / 0.01° 容差内视为通过。
- 结果（`tools/ik_experiments/elbow_branch_scan.py`，12 组伸出再拉回）：肘部翻转 0、暂停 0、手臂最大 360°/s、每周期 p95 约 3.4 ms。拉回后自动回到 Home 只有 3/12，留待后续；需要精确回 Home 时用一键复位。
- fairino_ik 改为 git submodule；上游分支 `feat/pinocchio-4.1.0` 已推送到 origin。

## 第 2 步设计

2026-11-19 第三版。前两版都被 Codex 的动手前审查拦下，共六处，均已核实并修正：

- 第一版：J17 的处理与启动余量冲突；「折叠三轴关节偏差恒定」不是可复算的不变量；碰到边界或回退时让躯干当周期停住，指令减速度达 450°/s²。
- 第二版：「完整目标误差不得比上周期大」与躯干平滑减速不能同时成立（目标已到位、腰从 0.5°/s 减速一帧，误差就从 0 变成 0.014 mm）；`direct_positions()` 的旧行为是 J15–J20 取保持值而不是当前值，「永远保持当前值」与「旧输出不变」冲突；包络按起点放宽后含越限点（起点前倾 −0.8° 时，高度降到 32.8% 处 j18 为 60.57°，超过 60°）。

依据是对 19 轴解的实测（Home 姿态，夹爪模式，目标超出臂展）：

| 目标 | QP 要的躯干 | 问题 |
|---|---|---|
| 双手前伸下探 | 前倾 10–33°，侧倾 0.04–0.6°，支点前移 50–115 mm | 前倾超过 5° 时任何非零侧倾都被 `validate()` 拒绝；支点离开升降路径 |
| 单手远伸 | 前倾 17°，侧倾 −7.4°，腰旋转 −7.5° | 同上；松开侧被解出 19° 的补偿运动 |

所以 QP 的躯干解只当作方向，下发的躯干目标由身体量重新构造。

**规则的优先级**（上面的优先；实现中发现规格内部不一致时按此裁决）
1. 旧协议不变：没有 `torso` 字段的 packet，`validate()` 和 `direct_positions()` 的结果与改动前逐字节相同；机器人端代码纯标准库。
2. 下发的手臂目标通过独立正解校验（0.02 mm / 0.01°，不放宽）和腕部保护。
3. 躯干指令的硬约束：只写 J16、J18、J19、J20；每周期每个关节的增量 ≤ `5°/s × dt`；支点偏移恒定；始终在会话包络内。
4. 正常跟随时躯干加速度有界，没有「当周期直接停住」的分支。
5. 手臂解不得比「手臂不动」更差。
6. 躯干只沿通过下降检验的方向加速。
7. 跟踪性能，以及「手臂够得到时躯干不动」。

「完整目标误差不得比上周期大」不是逐周期的硬条件：它与第 4 条冲突时第 4 条优先。躯干造成的误差增大由第 6 条限制在制动行程之内（最高速时每个关节 `v²/2a` = 1.25°）。

**躯干的自由度与路径**
- 躯干只有三个受控量：支点高度、前倾、腰旋转，对应 J16、J18、J19、J20 四个关节。J15（头）和 J17（侧倾）不在 packet 里，沿用旧行为取保持值；本后端没有任何地方改写这两轴的保持值，所以它们整个会话不动。
- 路径用「支点前后偏移」定义：`x0 = BodyModel.state(q)['forward_offset_mm']`，在本次遥操开始时由指令位置算出，之后恒定。高度（由支点 z）、前倾（三轴角度和）、偏移（支点 x）都是关节角的精确函数，与 J18–J20 一一对应，两端可以独立复算。已数值核对：按 x0 重建关节角的误差 1e-14°，沿升降全程 x0 的漂移 1e-13 mm。
- 由身体量反算关节角时用 `BodyModel.curve()`（不做校验）和一个 `x` 平移了 x0 的模型副本，不调用 `pose()` / `validate()`；包络检查由本模块自己做。

**固定系目标**
- 遥操目标必须固定在 base 系，否则躯干一动目标跟着动，形成正反馈。
- 不改现有 Clutch 类。每侧定义一个固定的虚拟臂基座系 V：`world_from_V = [R = CHEST_FROM_DH[side] 的旋转, t = 0]`。胸部竖直且腰旋转为零时胸部轴与 base 轴重合，所以在 V 里沿用现有 `BASE_FROM_TELEOP` 映射，手柄的前/左/上正好对应 base 的前/左/上（Codex 已核对：两侧 `R_V · BASE_FROM_TELEOP` 对单位阵的误差 2e-16）。
- 新输入类（`CartesianInput` 的子类）把「当前 TCP」和重定位用的 TCP 都换成 V 系表达；`FairinoQPIK.request()` 收到的目标在 V 系，内部左乘 `world_from_V` 得到 base 系目标。输入类的 `reset()` 同时复位躯干滤波器。
- 含义变化：其它三种 IK 的手柄方向跟随胸部；`fairino_qp` 的手柄方向固定在底盘。

**会话包络与启动条件**（启动时由指令位置算一次；不满足则拒绝，提示用身体程序调整）
- `|J17 指令| ≤ 0.2°`，按零侧倾处理。`|x0| ≤ 5 mm`。
- 起点：高度 ≤ 101%、前倾 ∈ [−1°, 46°]、|腰旋转| ≤ 91°，且换算后在 URDF 限位内。
- 包络是一个盒子：前倾 `[min(0, 起点), max(45, 起点)]`，腰旋转 `[min(−90, 起点), max(90, 起点)]`，高度上界 `max(100, 起点)`。高度下界 `h_lo` 按本次的 x0 和包络内最不利的前倾（下界）数值求出：全部 URDF 限位成立的最低高度再加 0.5%。x0 = 0、前倾下界 0 时约 32.8%；前倾下界 −1° 时约 34.9%。
- 盒子构造后做网格核对，任何一点超出 URDF 限位就拒绝启动；起点高度低于 `h_lo` 也拒绝。这样滤波器只需相对盒边制动，正常运行不会碰到 URDF 限位。

**每周期流程**（`s` 为身体量，`u` 为其速度，都是滤波器状态；`dt` 取本地单调时钟差并限制在 20 ms 内，时钟可注入；间隔超过 0.25 s 则 `u = 0` 并从 `hw.command_position` 重新取 `s`）
1. 躯干固定在当前 `s`，解双臂（迭代上限 `N_ARMS`）。对握住 Grip 的各侧算 base 系残差，取 `g = clamp(max(位置残差 / W_mm, 姿态残差 / W_deg), 0, 1)`；残差在 0.02 mm / 0.01° 以内时 `g = 0`。
2. `g > 0` 时解 19 轴：手臂从第 1 步的解出发，`arms_first_iterations = 0`（否则迭代预算全花在只动手臂的阶段），迭代上限 `N_BODY`。只取方向 `d = state(解) − s`，丢弃侧倾。下降检验：手臂关节不动、躯干沿 `d` 走一小步后，握住侧的 base 系误差必须减小，否则 `d = 0`。期望速度 `u_des = g · d / ‖J(s)·d‖∞ · 5°/s`，`J` 是身体量到四个关节的雅可比。目标刚越出臂展时 `g` 从 0 连续增大，所以在可达边界附近不会来回切换。
3. 滤波：`u` 向 `u_des` 靠拢，变化率受限；离盒边距离为 `D` 的方向上速度不超过 `sqrt(2·a·D)`，所以到边界前已经减速到零；最后把这一步整体缩放，使四个关节的指令增量都 ≤ `5°/s × dt`。关节加速度的设计值是 10°/s²。得到 `s_new` 和躯干目标 `T_new`。
4. `T_new` 与上周期不同时，在 `T_new` 下重解双臂（迭代上限 `N_ARMS`）。
5. 校验，任何一项不过都抛 `ValueError`：
   - 手臂用 DH 正解对求解器、躯干链用 numpy URDF 正解对求解器，阈值 0.02 mm / 0.01°。
   - 握住侧在 `T_new` 下，「手臂新解」的 base 系误差不得大于「手臂关节不动」的误差（度量与 `TronIK` 相同）。
   - 腕部保护的路径检查与缩放回退沿用 `TronIK._entry` 的结构，重解时躯干固定在 `T_new`。
   - `T_new` 超出会话包络或 URDF 限位（按设计不会发生）。
- 单侧 Grip：松开侧的关节解一律丢弃，packet 里不出现该侧；它在各次求解中的目标取能让它保持关节不动的位姿，每周期重新取。
- 斜坡宽度 `W_mm`、`W_deg` 要取得足够宽，使躯干能在加速度限制内跟上期望速度的变化，否则目标突然变得够得到时躯干会过冲再反向。躯干转 1° 约带动 TCP 12 mm，按 5°/s 和 10°/s² 估算 `W_mm` 至少 30 mm；由闭环仿真定值。
- 躯干只在手臂够不到时才动，够到即减速停下，所以辅助之后手臂会停在接近伸直的位置。这是「手臂优先」的直接结果。

**正常减速与保护性停止**
- 握住 Grip 正常跟随时，躯干指令只来自滤波器：期望方向消失、接近包络边界、反向，都按加速度限制减速。减速途中误差可以暂时增大。
- 松开双侧 Grip、暂停、`ValueError`、断流：沿用现有的全部 20 轴立即保持，与其它三种 IK 相同，不受加速度限制。躯干此时最多从 5°/s 瞬停；现有身体预设升降取消时是从 30°/s 瞬停。

**packet 协议**
- 顶层增加 `torso = {target: [J16, J18, J19, J20], path_offset_mm: x0}`（rad、mm）。仅 `ik_backend == 'fairino_qp'` 允许且必须携带。
- 每侧 `tcp` 仍是臂基座系 TCP，机器人端的手臂校验不变。每侧另带 `teleop_tcp`（V 系，仅客户端重定位用）。
- `vr_core.validate(hw, request, now, tools=None, body=None)`：`fairino_qp` 必须传入 `body`（`BodyModel`，按鸭子类型使用，`vr_core` 不新增 import，保持纯标准库）。无状态检查：
  - 4 个有限值；`|hw.command_position 的 J17| ≤ 0.2°`。
  - 把 4 个值代入 `hw.command_position` 得到完整姿态，换算到 URDF 后在限位内（`vr_core` 里放一张限位表，单测保证与 URDF 和适配器的映射一致）。
  - 身体量：高度 ∈ [−1, 101]、前倾 ∈ [−1, 46]、|腰旋转| ≤ 91。会话包络是它与 URDF 限位的子集。
  - 路径：`|path_offset_mm| ≤ 5`；目标姿态和 `hw.command_position` 的支点偏移与 `path_offset_mm` 相差都 ≤ 0.05 mm。
  - 相对 `hw.command_position` 的跳变 ≤ 1.5°。
- `direct_positions(current, targets, held, torso=None)`：与不带 `torso` 的调用相比，输出只在 J16、J18、J19、J20 四个位置不同；J15、J17 仍取 `held`。
- 第 3 步在机器人端补上：同一次遥操里 `path_offset_mm` 必须逐帧相同；按实际时间间隔检查躯干指令速率；下发躯干目标时同步更新这四轴的保持值；`vr_client` 调 `validate()` 时传入 `body`。
