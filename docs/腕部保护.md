# 可切换腕部联合限位

工作台的 **关节、TCP、PICO 遥操** 页面都有“腕部联合限位”开关，默认启用。
独立关节与 TCP 窗口复用同一个控件；独立 PICO 终端按 `g` 启用、`G` 停用。
显式停用后只取消本模块检查，厂家故障、急停、通信超时及各控制程序原有检查继续生效。

## 使用

```bash
bash run.sh console
# 或独立使用：
bash run.sh joints --group left
bash run.sh tcp
bash run.sh vr
```

运行中可以切换，无需关闭工作台。切换流程：

1. 清掉当前目标，暂停并保持使能；正在执行的 Home 也会中止。
2. 机器人完成停止，确认没有正在运行的轨迹，实测速度低于现有静止门槛；
   硬件提供指令速度时也检查该字段。停止流程还会核对位置保持指令。
3. 电脑与机器人确认模块版本、边界摘要、启用状态和本次切换序号。
4. 界面显示“已启用”或“已停用”。关节重新执行目标、TCP 松键重按、PICO 松开 Grip 后重握才继续。

握手没有完成时不接收新运动目标；旧序号、旧配置、缺少模块或版本不一致都不会静默绕过。
独立程序默认开启；工作台 PICO 页在本次打开期间保留你的勾选，启动下一会话会沿用，
重新打开工作台恢复默认开启。PICO 可用
`bash run.sh vr --no-wrist-guard` 显式以停用状态启动。
模块源码或边界数据更新后需结束当前控制会话并重新启动，以便把同一版本发送给机器人。

## 保护范围与动作

覆盖左腕 **J6/J7**、右腕 **J13/J14**：前臂外壳 `forearm2_Link`
与末端腕壳 `waist2_Link` 的相对关系。上游关节只使这对壳体整体变换，
因此本地腕部关系由最后两个关节共同决定。

- **关节单步 / 绝对目标**：机器人端检查整条关节路径，越界目标被拒绝，保持使能。
- **TCP 连续键控**：保留逆解所得速度方向，接近边界时整体降低速度。
  检查完整的三次 Hermite 轨迹和减速尾段，包括速度反向导致的内部极值。
- **PICO**：接近边界时缩小笛卡尔目标，再求 IK；保持目标 TCP 与关节解一致。
  限制后重新设置手柄锚点并清空该臂插值缓存，剩余位移不会在回到允许区后补走。
  机器人端独立检查上一指令、实测位置到新目标的腕部路径。
- **Home**：启动前检查起点到终点的整条共同五次进度路径，并加入峰值速度预测余量。
  两个端点合格而中途越界的轨迹会被拒绝；本模块不会自动绕行。

如果当前姿态落在预留余量带中，可手动让两个腕角绝对值减小或保持来退出；
接近边界时反向退出不受接近减速倍率限制。检测到已经位于模型相交区时不自动生成脱离动作。

## 边界来源和余量

`wrist-envelope-20261020-v1` 使用 2026-10-20 离线网格扫描。
模型为 `models/whole_body_20260731.urdf`，
SHA-256：`d64b19f6fc825ecdd2c97dbeb26514f844cba2ce28fa010864c0eed11e190cbe`。
扫描时的网格清单（可由 `git show b80f539:models/whole_body_meshes/manifest.json` 取回）的 SHA-256：
`b8fee3ca43ca2dc893f63c423acc48ab8bfe63a020cd2bbc51ac6913bfca23e0`。

工作台和遥操已切换至 RD53 20261030。腕部保护继续使用上述原始标定表；该表尚未通过 RD53 网格重新标定。

扫描记录位于 `logs/20261020-wrist-interference/`，其中 `boundary-left.json`
和 `boundary-right.json` 保存最后未检出相交角度 / 首次相交角度。
J6/J13 的主采样间隔 2°，J7/J14 边界细化到 0.1°。
内置表取左右臂、正负方向的较小值；格间取较低上限，未扩大到线性插值得到的区域。
扫描中的 ±51.971206° 补充点与 52° 格点的保守边界一致。

按 2026-10-20 的调整，默认在**两个角度方向分别侵蚀 2°**，
并在剩余 5° 范围内逐渐减小接近速度 / 目标。2° 是安全余量，不是固定腕角限位。
例如 J6=52° 时，计算 J7 上限使用 `边界(|52|+2)-2`，得到约 **±37.7°**；
J6/J13 的模块范围最多为 ±68°。这是针对壳体干涉的附加限制，不改写厂家固件。
PICO 另用当前实测腕速 × 0.20 秒扩大预测包络；TCP 使用其完整减速尾段。
配置摘要包含安全余量，使用旧 5° 配置的会话无法与新配置完成握手；更新后需重新启动控制会话。

这些数值来自有限采样的外观三角网格，是保守的软件试验边界，仍可能漏掉模型未表达的干涉。
2° 余量、5° 减速带及 0.20 秒没有经过实机制动标定；PICO 当前仍使用单点位置跟随，
预测包络不等同于真实刹停保证。模块不覆盖线缆、夹爪碰环境、双臂互撞或全身碰撞，
也不提供安全等级认证。首次使用保持低速，核对实机腕壳与模型的一致性。

## 模块接口

共享核心位于 `apps/fairino_upper_probe/wrist_guard.py`，只依赖 Python 标准库，
运行时无需加载 CAD、VTK、GTK 或 ROS。控制器适配与显示分离：

| 接口 | 用途 |
|---|---|
| `WristGuard.arm_segment(start, target, velocity=None)` | 七轴弧度向量的局部腕部路径与预测包络 |
| `WristGuard.segment(start20, target20)` | 二十轴目标的双腕路径 |
| `WristGuard.trajectory(points)` | 三次轨迹控制包络及停止尾段 |
| `WristGuard.approach_scale(start, target)` | 只缩小接近边界的动作 |
| `GuardClient` / `GuardSession` | 热切换握手、配置一致性、旧目标隔离 |
| `wrist_guard_ui.GuardControls` | 共享 GTK 开关与状态显示 |

关节、身体、TCP、PICO 的 SSH 启动包都携带同一份共享模块；界面不复制边界计算。
模块算法和适配层的离线测试覆盖相交例子、非凸路径、轨迹内部极值、减速反向、
双端切换、缺失 / 错版 / 旧目标、真实厂家 IK 的 TCP 一致性与 Home。
通信压测分支仍可发送模拟目标，该分支没有运动发布接口。
